# Руководство по системе визуализации экипировки

## Обзор системы

Система `PlayerEquipmentVisuals` теперь поддерживает отображение всех типов экипировки на персонаже, включая:

- **Оружие**: Мечи, луки, посохи (одноручное и двуручное)
- **Броня**: Шлемы, нагрудники, поножи, ботинки, перчатки
- **Аксессуары**: Кольца, ожерелья (пока без визуального отображения)

## Структура костей персонажа

Для корректной работы системы на **активной модели персонажа** (определяемой через ClassData) должны быть следующие кости:

> **Важно**: Система теперь ищет кости только в активной модели игрока, определяемой через `ClassData.modelPrefab` в `PlayerAnimationSystem`. Это обеспечивает корректное отображение экипировки для каждого класса персонажа.

### Рекомендуемая структура (специализированные слоты):

```
Персонаж
├── RightHandWeapon    (правая рука - оружие)
├── LeftHandWeapon     (левая рука - оружие/щит)
├── HelmetSlot         (шлемы)
├── ChestArmorSlot     (нагрудники)
├── LegArmorSlot       (поножи)
├── BootSlot           (ботинки)
├── GloveSlot          (перчатки)
├── RingSlot           (кольца)
└── NecklaceSlot       (ожерелья)
```

### Альтернативная структура (использование основных костей):

```
Персонаж
├── RightHandWeapon    (правая рука - оружие)
├── LeftHandWeapon     (левая рука - оружие/щит)
├── Head               (голова - шлем)
├── BodyVisual         (тело - нагрудник)
├── Legs               (ноги - поножи)
├── Boots              (стопы - ботинки)
└── Gloves             (кисти - перчатки)
```

### Преимущества специализированных слотов:

- **Лучший контроль позиционирования** - каждое оборудование имеет свою точную позицию
- **Избежание конфликтов** - разные типы экипировки не мешают друг другу
- **Гибкость настройки** - можно настроить разные позиции для разных типов предметов
- **Легкость отладки** - четкое разделение между слотами экипировки

## Настройка предметов экипировки

### Обязательные поля для каждого предмета:

1. **model1** - Путь к префабу модели в папке Resources
2. **boneName** - Имя кости для крепления модели
3. **modelRotation** - Поворот модели относительно кости
4. **modelScale** - Масштаб модели
5. **equipmentSlot** - Слот экипировки
6. **primaryDisplaySlot** - Основной слот отображения

### Пример настройки шлема:

```csharp
// В Inspector предмета:
model1 = "Equipment/Helmets/IronHelmet"
boneName = "Head"
modelRotation = Quaternion.Euler(0, 0, 0)
modelScale = Vector3.one
equipmentSlot = EquipmentSlot.Head
primaryDisplaySlot = EquipmentSlot.Head
```

### Пример настройки двуручного меча:

```csharp
// В Inspector предмета:
model1 = "Equipment/Weapons/GreatSword"
boneName = "LeftHandWeapon"
modelRotation = Quaternion.Euler(0, 90, 0)
modelScale = Vector3.one
equipmentSlot = EquipmentSlot.LeftHand
primaryDisplaySlot = EquipmentSlot.LeftHand
isTwoHanded = true
```

## Особенности двуручного оружия

- Двуручное оружие всегда отображается на кости `LeftHandWeapon`
- При экипировке двуручного оружия очищаются оба слота рук
- Двуручное оружие можно экипировать только в слот `LeftHand`

## Процесс экипировки

1. **Инициализация**: Система проверяет наличие всех необходимых костей
2. **Обновление**: При изменении слота вызывается `UpdateEquipmentVisual`
3. **Очистка**: Удаляются предыдущие модели из слота
4. **Установка**: Создается новая модель и прикрепляется к кости
5. **Позиционирование**: Применяются поворот и масштаб

## Отладка

Система выводит подробные логи для отладки:

- Найденные кости в активной модели при инициализации
- Предупреждения о отсутствующих костях в активной модели
- Информация об экипировке/снятии предметов
- Fallback к полной иерархии если активная модель не найдена

### Проверка активной модели
Система автоматически определяет активную модель через `PlayerAnimationSystem.GetActiveModel()` и ищет кости только в ней. Это обеспечивает корректное отображение экипировки для каждого класса персонажа.

## Расширение системы

Для добавления новых типов экипировки:

1. Создайте новый класс предмета (например, `ShieldItem`)
2. Добавьте соответствующий слот в `EquipmentSlot` enum
3. Обновите `GetBoneNameForSlot` метод
4. Добавьте проверку кости в `Init` метод
5. Создайте соответствующий UI слот

## Известные ограничения

- Кольца и ожерелья пока не имеют визуального отображения
- Система не поддерживает динамическое изменение цвета/материала
- Нет поддержки анимации экипировки при надевании/снятии
